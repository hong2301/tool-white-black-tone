# 白黑调色 · Dark Mode

一个 Chrome 扩展（Manifest V3）：**识别页面里的白色系与黑色系，按色系排列给出对应的深色 / 浅色**，一键开关、按站点记忆，并自动跳过本身已经是深色的页面。

---

## 一、它做什么

### 核心一：识别

遍历页面每个元素的计算样式（含 open shadow DOM），把颜色按**用途**分成三类，各自统计明度排列：

| 类别 | 来源 | 典型颜色 |
| --- | --- | --- |
| `surface` 背景 | `background-color`、渐变里的色标 | `#ffffff` `#f5f6f8` `#eef1f6` |
| `text` 文字 | `color`、`-webkit-text-fill-color`、SVG `fill/stroke` | `#111111` `#333a45` `#6b7280` |
| `line` 线条 | 四条 `border-*-color`、`outline`、`text-decoration`、`box-shadow` | `#e4e7ec` `#d7dbe3` |

### 核心二：转换（保序色阶，只有「纯黑」一档）

不是简单反色，而是把观察到的**色系排列**拉伸到目标色阶：

（下面是演示页 `test/demo.html` 打开后的真实输出，弹窗里看到的就是这张表）

```
白色系（原色越白 → 目标越亮）        纯黑主题
#ffffff  ──────────────────────▶ #1c1c1c   卡片 / 抬升面
#f5f6f8  ──────────────────────▶ #111317   页面底色
#eef1f6  ──────────────────────▶ #060708   最低的浅色面
#2f6bff  ──────────────────────▶ #064af1   品牌色（只压暗一点，色相不变）
#e6f7ee  ──────────────────────▶ #070c09   淡绿底 → 深绿底

黑色系（原色越黑 → 目标越亮）
#101012  ──────────────────────▶ #efeff1   主标题
#55607a  ──────────────────────▶ #b7bdcb   三级文字
#6b7280  ──────────────────────▶ #b4b8bf   正文
#8b94a3  ──────────────────────▶ #9fa5b1   次要 / 提示文字

浅色边框（原色越深 = 越强调 → 目标越亮）
#e4e7ec（弱）──────────────────▶ #22262d
#d7dbe3（强）──────────────────▶ #424957
```

要点：

- **保序**：原色越白 → 目标越亮（保持"越高越突出"的层次感，卡片不会比页面更暗）；原色越黑 → 目标越亮（主文字最亮，次要文字更暗）。
- **感知背景**：每个元素先算"自己所处的背景明度"。深色块（hero、深色导航、深色控制条）里的文字原样保留，不会被压暗；浅色块里的黑/灰字才按色阶提亮。所以同一个页面里"白底灰字"和"深底浅字"都能各就各位。
- **按实际色系拉伸**：用页面里真实出现的色系分布（5%~95% 分位，剔除离群色）决定色阶范围，所以纯白系页面和灰阶丰富的页面都能得到清楚、不糊的层次。
- **彩色不动色相**：品牌蓝按钮仍是蓝；淡色底（`#e6f7ee` 这类）会变成对应的深色底。
- **深色区域保留**：原本就深色的导航 / hero 不会被反向搞亮。
- **图片 / 视频 / canvas / iframe 原样保留**，渐变里的 `url(...)` 也不碰。

### 核心三：智能跳过

按**面积加权**统计每个元素的不透明背景色明度，得到整页的深浅占比：

- 深色面积占比 ≥ 60% → 判定「这个页面本来就是深色」，**不应用任何转换**（`已跳过`），因为插件只适配没有深色模式的页面。
- 想强行应用，点弹窗里的「仍然应用」，该站点会一直被强制（可随时取消）。
- 设置里可以关掉「页面已是深色时跳过」。

### 核心四：怎么落地（不写 inline，避免"一直在改颜色"）

早期版本是逐元素写 `style="... !important"`，问题很明显：

- 几千次 `setProperty` → 触发元素样式重算
- 写 `style` 又会被 MutationObserver 捕获 → 再次扫描 → 再写，形成自激循环，页面一动就反复干活

现在改成两层，**DOM 只动一次属性，颜色只写一条规则**：

| 层 | 做法 |
| --- | --- |
| CSS 规则表 | 一种颜色只生成一条 `[data-dm][data-dm-bg="12"]{background-color:#1c1c1c !important}`，整张表放在一个 `CSSStyleSheet` 里（`adoptedStyleSheets`，绕开页面 CSP） |
| 元素标记 | 元素上只写 `data-dm-bg="12"` 这类属性，值就是颜色编号 |

实测：6000 元素的页面，14800 次属性写入只映射出 **59 条 CSS 规则**，扫描 200ms，之后 DOM 完全静止（外部 MutationObserver 计数不再增长）。

**页面 CSS 变量也一并覆盖**（可以在弹窗里关掉）：扫描 `--bg` `--text-primary` 这类变量，用同一套色阶算出新值写进 `:root`。变量该走背景还是文字色阶，看它在页面上主要被哪类元素使用。这样连以后动态插入的内容都会自动跟随。

**观察器策略**：只监听节点增删（`childList`），不监听属性变化；已处理过的元素用 `WeakSet` 记住不再重算；页面越吵，节流间隔自动从 160ms 拉长到 1.2s，空闲 3 秒后复位。

### 交互：只有一个开关

弹窗里只有一个开关，没有别的任何东西：

```
┌──────────┐        浅色：白色轨道 + ☀ 圆钮在左
│    ◐ ●━  │        深色：深色轨道 + ☾ 圆钮在右
└──────────┘
```

弹窗尺寸随内容自适应（约 80×52），不看域名、不看色表、不看统计。

开关本身就是状态：轨道颜色和圆钮里的图标一眼就能分辨「页面现在是浅色还是深色」。

- **记忆**：状态按站点（hostname）记忆；新站点沿用最后一次选择。
- **还原无损**：`data-dm-*` 属性与那 60 来条 CSS 规则一起撤掉，页面回到原样，不留空 `style`。
- 页面本身是深色时，多出一行「页面本身是深色，已跳过」+「仍然应用」。
- 没有角标、没有设置面板、没有颜色表。

## 二、安装

1. 打开 `chrome://extensions`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录
4. 若要作用在本地 HTML 文件，需在扩展详情里打开「允许访问文件网址」

支持 Chrome / Edge 96+。可加载的目录就是本目录根（含 `manifest.json`）。

### 目录可以移动吗？

可以。`manifest.json` 里已经带了固定的 `key`，扩展 ID 被钉死为：

```
iaoebinnfpeabfdcejanjofcgilfhfck   ← 实际值见 node scripts/gen-key.js 的输出
```

所以**移动目录不会改变扩展 ID**，`chrome.storage` 里记住的各站点开关不会丢。

移动后仍要做一次重载，因为 Chrome 记的是旧的绝对路径：

1. 打开 `chrome://extensions`
2. 找到本插件 —— 路径失效时会标红报错
3. 点「移除」，再「加载已解压的扩展程序」选新目录
4. 给 `file://` 用的「允许访问文件网址」需要重新勾选

> 如果没加 `key`：未打包扩展的 ID 是**由绝对路径哈希**出来的，移动目录 → ID 变 → 记忆数据全丢。这就是加 `key` 的原因。
> `key` 一旦生成就不要再改，改了 ID 会变。想重新生成请先删掉 manifest 里的 `key` 字段再跑 `node scripts/gen-key.js`。

### 「当前页面不可用」是怎么回事

弹窗连不上页面里的注入脚本，会分情况说明原因：

| 情况 | 提示 |
| --- | --- |
| `chrome://` `about:` 扩展管理页 | 浏览器自留地，任何扩展都不能注入，属正常 |
| Chrome 应用商店 | 官方禁止扩展运行 |
| `file://` 本地文件 | 需要打开「允许访问文件网址」 |
| 普通网页 | **刷新一次页面**即可（脚本只在页面加载时注入），也可点弹窗里的「注入到当前页」直接补注入 |

## 三、目录结构

```
manifest.json
icons/              # 图标（由 scripts/make-icons.js 生成）
src/
  color.js          # 颜色解析 + 保序色阶映射（核心二）
  engine.js         # DOM 遍历 / 识别 / 写入与还原 / 明暗检测（核心一、三）
  background.js     # service worker：首次安装写入默认设置
  popup.html/.css/.js
scripts/
  make-icons.js         # 零依赖生成 PNG 图标
  make-popup-preview.js # 生成 test/popup.html（注入 mock chrome API）
test/
  demo.html         # 浅色演示页（应被转换）
  demo-dark.html    # 深色演示页（应被自动跳过）
  mock-chrome.js    # 不用装扩展也能在浏览器里跑引擎
  popup.html        # 弹窗 UI 预览
```

## 四、本地验证（不用装扩展）

```
node scripts/make-icons.js
node scripts/make-popup-preview.js
```

然后直接用 Chrome 打开：

- `test/demo.html` —— 点右下角「开启」，页面变纯黑，面板里能看到色系映射表
- `test/demo-dark.html` —— 点「开启」，应显示 `skipped=true`、不写入任何样式
- `test/popup.html` —— 弹窗 UI（`?mode=dark` 看跳过态、`?mode=na` 看不支持态）

## 五、已知边界

- 落地方式为 `data-dm-*` 属性 + 一条 `!important` 规则（specificity `0,2,0`）。极少数用 `#id ... !important` 覆盖的站点可能压不住，此时该元素保持原色。
- 颜色种类超过 1500 种时自动降级为逐元素内联写入（渐变生成色特别多的站点）。
- 样式画在 `::before/::after` 伪元素上的背景覆盖不到。
- 因为用 `!important` 固定了颜色，页面自己的 hover / 过渡变色会被一并冻结（这是本方案的既有取舍）。
- 单次扫描上限 2 万个元素，超大页面会截断（弹窗会标注「已截断」）。
- 跨域 iframe 由浏览器按 `all_frames: true` 各自注入，互不影响。
- 页面自身带图片背景（`background-image: url(...)`）的区域只改底色，不改图。
